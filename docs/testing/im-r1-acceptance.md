## 3. 预发升级与回退演练

环境：本机沙箱中的 MySQL 8.4.13（官方 Debian 12 包，默认 `sql_mode`）。旧版本是 `origin/main@e89cda9` 构建的二进制，新版本是验收提交构建的二进制。时间 2026-11-18 15:28–15:33。

**升级前数据**：全部由旧版本 API 写入。

- 4 个企微配置：
  - 对话 A、对话 C；
  - 通知 B1、B2，共用同一个 Bot ID；
  - 另有一次重复启用被旧版本拒绝（409）。
- 4 条绑定：
  - 正常 1 条；
  - 共用 Bot ID 1 条；
  - 孤立 1 条；

## 4. 行为变更测试：自然语言回答

基线对照：在 `origin/main` 上，模型对查询给出纯自然语言回答、不调用终态工具时，会运行 3 次模型，最后返回“助手未提交回复”。

`internal/httpapi/bot_natural_reply_test.go` 的 9 种情况全部通过：

| 情况 | 模型运行次数 | 结果 |
| --- | --- | --- |
| 自然语言回答（旧企微，自动执行） | 1 | 采用 |
| 自然语言回答（只读） | 1 | 采用 |
| 首轮只有进度（“我先查询一下”），第二轮给出回答 | 2 | 采用第二轮的回答 |
| 首轮空输出，第二轮给出回答 | 2 | 采用第二轮的回答 |
| 带草稿的协议 JSON | 3 | 不采用，失败 |
| 不带草稿的协议 JSON，第二轮给出回答 | 2 | 不采用 JSON，采用第二轮的回答 |
| CLI 退出失败（输出了回答） | 3 | 不采用，失败 |
| 三次都没有输出 | 3 | 失败 |
| 回答里带个人凭据 | 1 | 采用，凭据替换为 `[redacted]` |

这组测试发现并修复了一处问题：协议 JSON 中的草稿在解析时被过滤后，剩下的“将创建需求”曾被当作回复发出。现在只采用纯文本。

# 节点工作区检查点

包含 Git 仓库的普通工作流默认启用节点检查点；可以在项目设置中关闭。没有仓库的运行和对话工作区不启用，子 SOP 继承父运行的设置。

Agent 或脚本节点开始尝试前，LoopForge 会为运行中的每个 Git 仓库保存工作区快照；尝试结束后再记录一次，以便查看该次尝试的改动。快照使用私有 Git 引用，不移动分支或 HEAD，也不改变正常的 Git 历史。工作分支推送不会包含这些私有引用。

快照覆盖 Git 已跟踪的文件和未被忽略的新文件，与 `git add -A` 的范围一致。`.gitignore` 忽略的文件（例如依赖目录）不包含在快照中，因此不会被恢复。快照需要读取文件并写入 Git 对象；仓库越大、文件越多，节点开始和结束时的耗时及磁盘开销可能越大。

节点运行时可以查看从起始检查点到当前工作区的近似即时差异。正在写入的文件可能使快照失败，此时可以重试；节点结束后的差异基于起止快照。启用检查点时，共用工作区的受管理节点执行会串行化。如果目标检查点之后其他节点修改过工作区，恢复会被拒绝。

当前实现不能证明节点启动的后台进程已全部退出：脱离节点生命周期的本地进程或容器进程仍可能在节点结束或租约过期后修改工作区，其修改可能混入差异或被恢复覆盖。部署前需要明确并解决这些进程的隔离和生命周期问题。

`full_redo` 重试会尝试恢复节点第一次尝试之前的状态；`targeted_fix` 在上一轮结果上继续，并在反馈中附上变更文件列表。评审打回时也可以选择恢复上游节点的起始状态。恢复前会记录当前工作区作为恢复点，可用于撤销回滚。

人工回滚仅允许在运行等待或失败、工作区尚未回收且没有活动执行任务时进行。恢复会将目标节点及其下游节点重置为待执行，并记录操作者和 `workspace.rewound` 事件。子 SOP 可从自己的运行详情回滚；共享同一工作区的父运行和其他子运行必须先停止。其他节点在目标检查点之后的修改仍受冲突检查保护。

恢复要求当前分支和 HEAD 与检查点一致，且不能存在进行中的合并、变基等 Git 操作；子模块、嵌套仓库或可能被覆盖的忽略文件也会导致恢复被拒绝。恢复后的文件改动保留在工作树中，原有暂存状态不予保留。多个仓库会先逐一检查，再执行恢复；恢复中断时会保留恢复点并阻止运行继续，直到处理故障。

Runner 持久记录检查点操作期间的工作区占用。Runner 异常退出或执行被取消后，该标记可能继续阻止新的写入与回收；处理前必须确认旧的本地进程及容器进程已全部停止。此保护目前没有自动解除入口。

工作区归档排除检查点的私有引用和引用日志，但 Git 对象库中仍可能保留检查点产生的不可达对象。

# SOLO 阶段规则

1. 仅处理单模块、预计不超过 3 个文件且不涉及接口、数据模型、迁移、架构或高风险发布的小型任务；发现超限立即报告 overflow。
2. 在同一上下文中依次完成最小计划、实现、自审和针对性测试，不因合并阶段而跳过证据、边界检查或真实验证；涉及用户旅程或跨边界行为时运行现有集成/E2E，确实不适用时说明理由。
3. 保护用户已有改动，只做目标所需的最小修改；最终报告列出实际文件、命令、结果、偏差和剩余风险。
4. HTTP API 有新增、修改或删除时，从 `templates/api-docs.md` 生成并填写 `01-solo/api-docs.md`，在报告中写“已生成：`01-solo/api-docs.md`”。无接口变动时明确写“无接口变动”。

# IMPLEMENT 阶段规则

1. 先读取执行计划、项目规则和目标文件；只实现计划内行为。发现计划缺失、证据冲突或需要扩大产品范围时停止并报告，不静默自行设计。
2. 保护用户已有改动；修改前读取现状，避免覆盖无关 diff，不顺带重构、统一风格或升级依赖。
3. 按依赖顺序和目标文件执行任务；每批最多处理 3 个相关任务。共享文件、迁移或生成步骤存在顺序关系时串行。
4. 沿用项目现有错误处理、配置、日志、测试和依赖方式；禁止硬编码凭据、内部地址或环境专属值。
5. 实现同时完成执行计划明确要求的单元、集成、契约或 E2E 测试；不得把计划内测试统一推迟给 TEST 阶段。每批先运行最窄验证，再运行计划要求的静态检查、测试或构建，只记录实际结果。
6. 变更报告逐项对应实际修改、验证证据、计划偏差和剩余风险；不要批准自己的实现。
7. 对照实际 diff 判断 HTTP API 是否新增、修改或删除。若有，复制 `templates/api-docs.md` 生成并填写 `03-code/api-docs.md`，在 change report 中写“已生成：`03-code/api-docs.md`”。若无，明确写“无接口变动”。

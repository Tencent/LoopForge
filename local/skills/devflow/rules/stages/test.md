# TEST 阶段规则

1. 从设计阶段记录的测试能力开始，只在证据缺失或实现发生偏差时重新扫描测试目录、配置和 CI；复用项目现有框架、夹具和命令，不引入不匹配的重型依赖。
2. 建立“验收标准/风险 → 项目已有的合适测试层级 → 用例或命令 → 结果”矩阵。若仓库已有 E2E，且本次行为落在其用户旅程、真实路由、跨进程/服务或持久化覆盖边界内，必须检查并补充相应用例；仓库没有 E2E 时不强制创建，只说明现有最高层级无法覆盖的风险。
3. 若关键覆盖缺失且可在现有框架内补齐，直接新增或修改测试与夹具并运行；只能修改测试相关文件和测试报告，禁止修改生产代码。生产缺陷或不可测设计应记录最小复现并使阶段失败，交回 IMPLEMENT。
4. 覆盖成功路径、输入边界、权限与安全边界、依赖失败、兼容性及高风险回归；优先最窄测试，再运行受影响范围的集成/E2E、静态检查或构建门禁，不为凑数量运行无关全集。
5. 保留工作目录、完整命令和关键结果，严格区分 passed、failed、blocked、not-run。环境阻塞时说明缺失条件、替代证据和未验证风险，静态阅读不能记为执行通过。
6. 报告矩阵、命令、结果和未运行项必须逐项对应；关键验收缺少可执行证据时不得通过。

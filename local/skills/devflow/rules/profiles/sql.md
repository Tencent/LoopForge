# SQL 与数据变更专项规则

1. 值参数必须参数化；动态表名、列名和排序字段必须使用明确白名单，禁止直接拼接不可信输入。
2. 结合真实查询模式检查索引、N+1、无界读取、深分页和锁范围，不使用“固定索引数量”等脱离项目证据的通用阈值。
3. 事务范围保持最小，明确提交、回滚、超时和失败重试语义；事务内外部调用或跨资源一致性必须说明风险。
4. 迁移必须考虑向前兼容、存量数据、重复执行、灰度期间的新旧版本共存以及可执行回滚；破坏性操作需要显式风险与恢复方案。
5. 审查和测试覆盖约束、空值、重复数据、并发写入、失败回滚及敏感数据处理；只依据实际 schema、查询和执行证据下结论。
6. 只读优先：查询默认只读；写操作必须先说明必要性、影响范围和回滚方案，未确认写意图前不得执行 INSERT、UPDATE、DELETE 或 DDL。
7. 行数与超时上限：查询必须有按项目约定的行数上限和超时，禁止无界读取；超限先收敛条件再执行，不得先全量拉回再过滤。
8. 审计：所有写操作和敏感查询必须留审计记录（谁、何时、哪条语句、影响行数），审计记录只追加不改写；只读查询的审计范围按敏感度定。
9. 行级权限：涉及多租户、多组织或多范围的数据，必须先确认行级隔离条件，不得假设调用者只能看到自己的数据；缺隔离条件就 fail-closed，停在当前阶段。
10. 敏感数据：密码、密钥、身份证号、手机号等敏感字段不得明文输出到日志、产物或审计记录，必要时只留脱敏形式；导出敏感数据须先确认授权。

# Go 专项规则

1. 以项目 `go.mod`、现有代码和项目指令为准，不擅自升级 Go 版本或依赖。
2. 修改的 Go 文件使用项目已有格式化/静态检查方式；通常至少运行 `gofmt`，仅在项目已有 `goimports` 时依照其约定使用。
3. 错误必须被处理或有意返回；包装错误保留因果链。资源释放紧跟成功获取之后，避免循环中的无界 `defer`。
4. 涉及 goroutine、channel、锁或 context 时检查取消、退出、竞态、泄漏和所有权；相关测试可行时运行 `go test`，并按风险考虑 `-race`。
5. 沿用现有包边界、命名和测试风格，不为满足通用偏好重构无关代码。

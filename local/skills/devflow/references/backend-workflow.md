# 后端流程

1. 识别服务入口、API/事件契约、数据存储、迁移工具、调用方和可观测性约定，以项目现有实现为准。
2. HTTP API 有新增、修改或删除时，必须从 `templates/api-docs.md` 生成本次任务的接口文档：IMPLEMENT 固定为 `03-code/api-docs.md`，SOLO 固定为 `01-solo/api-docs.md`。文档覆盖路由、方法、权限、请求、响应、错误和兼容性，并以实际代码为准。
3. 数据变更检查约束、事务、索引、存量数据、新旧版本共存和可执行回滚；并发路径检查竞态、取消、资源释放与重复请求。
4. 测试优先复用项目已有层级：单元逻辑、真实依赖边界的集成/契约测试；已有 API/异步链路 E2E 且本次改动属于其覆盖边界时必须补齐，未配置时不强行引入。不能只用 handler 单测代替项目已有的持久化、队列或跨服务测试。

通用流程、批次、Git 保护和报告规则由核心与阶段规则提供，本 profile 不重复注入。

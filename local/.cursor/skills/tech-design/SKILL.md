# 技术方案撰写技能

## 工作流程

### 第一步：解析需求输入

根据输入类型进行处理：

- **需求分析报告**：读取报告文件，提取需求背景、功能点、约束条件
- **口头描述**：直接理解用户描述，若信息不足以支撑方案撰写，追问以下关键信息：
  - 核心功能是什么？
  - 涉及哪些系统/模块？
  - 有无性能/安全特殊要求？
  - 预计数据量级？

### 第二步：加载方案模板

读取通用技术方案模板：[references/general.md](references/general.md)

### 第三步：撰写技术方案

按照模板结构生成技术方案，注意：

- 架构图、流程图、时序图统一使用 Mermaid 语法绘制
- 不涉及的章节（如灰度策略、第三方依赖）直接删除，不强行填写
- 若某章节信息不足，标注"待补充"并说明需要哪些信息
- 方案中的估算数据（性能指标、数据量等）需标注来源或假设依据

### 第四步：保存文档

将生成的技术方案保存为 Markdown 文件：

- 若用户已指定输出路径，保存到指定路径
- 若用户未指定路径，询问保存位置
- 文件名建议：`tech-design-[需求名称].md`

## 注意事项

- 方案内容应具体、可落地，避免空泛描述
- 关键技术决策需说明"为什么选这个，为什么不选那个"
- 复杂方案优先用图表表达，文字辅助说明

# Gate: CODE-REVIEW（代码审查门禁）

> 由 code-reviewer 在 CODE-REVIEW 阶段执行审查 + leader 他审审查报告质量。

## 必须通过（任一不通过则 FAILED）

### 前置硬校验（原 gate-task-03 合并）⭐
- [ ] **越界检查**：实际变更文件 ⊆ execution-plan.md 中所有 PT 的 `files_whitelist` 并集（任一越界文件 → 直接 FAILED）
- [ ] **acceptance 完成度**：所有 PT 的 acceptance 项均已验证且结果为 PASS（change-report.md 中 Acceptance 验证结果表格无 FAIL 项）
- [ ] **API 文档产物校验** ⭐：只要本次需求涉及 HTTP API 接口的**新增、修改或删除**（含路由变更、请求/响应结构变更、接口行为变更），则 `{artifacts_dir}/03-code/api-docs.md` 必须存在且非空；缺失则直接 FAILED 并要求 developer 补生成

### 代码质量审查
- [ ] **安全**：无 SQL 注入风险（所有 SQL 使用参数化查询）
- [ ] **安全**：无硬编码凭证（密码、密钥、Token 等）
- [ ] **安全**：用户输入已做校验和过滤
- [ ] **安全**：敏感操作有权限控制
- [ ] **性能**：无明显 N+1 查询问题
- [ ] **性能**：大数据量查询有分页或流式处理
- [ ] **性能**：新增/修改的 SQL 查询有合理索引支持
- [ ] **规范**：代码变更与 tech-design.md 设计一致
- [ ] **规范**：无未处理的错误/异常（panic、未捕获异常等）
- [ ] **规范**：关键业务逻辑有日志记录

## 建议检查（不强制，但鼓励）

- [ ] 函数/方法长度合理（单函数不超过 80 行）
- [ ] 命名清晰、自解释
- [ ] 有必要的注释（复杂逻辑、业务规则、hack 说明）
- [ ] 无冗余代码（dead code、注释掉的代码块）
- [ ] 事务控制合理（无长事务、有回滚处理）
- [ ] 并发安全（共享资源有锁保护或使用无锁结构）

## 评判标准

| 结果 | 条件 |
|------|------|
| **PASSED** | "必须通过"全部勾选，无严重问题 |
| **FAILED** | "必须通过"有未勾选项，或发现严重安全/性能问题 |
